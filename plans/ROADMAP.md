# zdos roadmap

Short index of what's built and what's next. **Keep this current** — add an entry when a
milestone/phase lands or a goal changes. Detailed plans live in `plans/`; session memory in
`.claude/.../memory/`.

## Now working
Real-mode 386 + DOS/BIOS core runs real BC3.1/TC++ programs deterministically. A full
**debugger** drives it: in-process control core + an **HTTP/JSON API** (breakpoints, step,
run-to-cycle, inspect/patch CPU+memory, **keyboard/mouse injection**, console read), with
in-process *and* black-box (real-binary-over-HTTP) test suites.

13. **Screenshot PNG API (`GET /api/framebuffer?format=png`)** — a host-side, lossless PNG re-encode of the existing cycle-neutral framebuffer peek (no new emulation, no cycle charge, no device mutation). New module `src/api/png.zig` (module `api`, ABOVE `devices`; NOT in the devices grep-gate, reads no emulated cycle counter, uses no host clock/RNG/float → output is a byte-identical function of the captured frame) encodes with `std.compress.flate.Compress` (`container = .zlib` → the zlib header + Adler32 ARE the IDAT payload) + `std.hash.Crc32` (= the PNG chunk CRC). Chunks: signature, IHDR, PLTE (indexed), IDAT (per-row filter 0/None), IEND. **Color type auto:** indexed (type 3 + 256-entry PLTE built from the DAC via the pinned `expand6to8`, with `pel_mask` applied to indices to match `indexToRgba`) when the mode is paletted — every current rasterizer kind — else truecolor RGB (type 2, alpha dropped). Raw logical resolution (no scaling/aspect/metadata). Reuses the existing `framebuffer_get` worker command; the worker also fills a server-owned 768-byte expanded PLTE slab + `palette_present`/`pel_mask` in the descriptor (all machine reads stay on the worker); the encode runs off-worker on the listener thread over the immutable snapshot into server-owned fixed slabs (`png_out` ~1.3 MiB + 64 KiB flate window + IDAT scratch, allocated once — no per-request alloc, never through `resp_buf`/JSON). `Content-Type: image/png`, `X-Frame-Format: png-indexed|png-rgb`; unsupported mode → 501 (no fake frame). 15. **Live-stream Phase 2 — paced free-run + run control + the multi-producer queue fix** — the concurrency-critical foundation for the live stream (the picture can now move). **(a) Submit-gate (correctness):** `CommandQueue` gains a dedicated `submit_gate: Io.Mutex` held across the ENTIRE submit-and-wait (`queue.zig` `submit`), so multiple host producers (the run-pacer, future frame/input producers) strictly SERIALIZE — the internal condvar `waitUncancelable` releases the inner mutex, so without the gate a 2nd producer would race the `head==tail` assert; with it the one-in-flight invariant holds BY CONSTRUCTION. Clockless (`*Uncancelable`), single-producer callers unchanged. **(b) `run_slice` worker command** = `runUntilEvent(slice_cycles)` (mirrors `.run`) — the bounded deterministic slice the pacer submits each tick. **(c) The run-pacer in `src/host/run_pacer.zig`** (NOT `src/api`, to keep the api determinism grep-gate intact — §5.1a): its own thread loops `submit(run_slice) via the gate → host-sleep the rest of a ~10 ms wall tick`; the HOST CLOCK (`io.sleep` + `.awake` elapsed read) lives ONLY here, outside the embedded api set. Armed/disarmed via the clockless atomic `RunControl.armed` the `/api/run/*` endpoints flip; self-DISARMS on a terminal slice (program_terminated/halted_forever/shutdown/breakpoint) — never spins a dead machine (§10). New `src/host/` module + `host` build module (imports `api`; reaches the worker ONLY via the gated queue). **(d) Run-ownership arbitration** — `RunControl` (`src/api/run_control.zig`, CLOCKLESS: atomics + a no-timeout mutex, embedded in the api grep-gate) holds `RunOwner = {idle, paced, debugger}`: `POST /api/run/start {slice_cycles?, fps?}` arms (owner=paced) or **409** if a debugger run is in flight; `POST /api/run/stop` disarms; `GET /api/run/status` → `{running, owner, cycle, slice_cycles, fps, last_stop_reason}`; `step`/`run`/`run-to-cycle`/`run-to-address` AUTO-DISARM the pacer for their duration (a debugger command always wins and lands deterministically) and re-arm after. **(e) Wiring:** `main.zig --serve` spawns the pacer after `bind`, registers its stop+join as the server's pre-shutdown hook so it is joined BEFORE the worker `shutdown_worker` sentinel (§9.1 — no producer races the sentinel). **Determinism (load-bearing):** paced ≡ unpaced, byte-identical machine state at the ACTUAL final cycle of a paced run (host sleep changes only wall-time pacing, never which cycles run — emulated time stays f(cycles); no smear). Tests (`test-host` + `test-api`): submit-gate two concurrent producers complete with no assert trip; paced≡unpaced byte-identity; pacer disarms on terminal; run-ownership (auto-disarm + 409 + status); the api determinism grep-gate still green (pacer clock in `src/host`). `zig build test` green, 506 tests; blackbox + the `--serve` endpoints verified end-to-end. The WebSocket/stream/player are later phases. → `plans/video-stream-api.md` (Phase 2 / §5).
16. **Live-stream Phase 3 — server-side WebSocket stream (handshake + per-conn threads + shared-frame producer + raw-indexed wire + dedup)** — the live picture now reaches the browser. **(a) WS upgrade:** `GET /api/stream` with the Upgrade headers is detected in `handleConnection` (via `Request.upgradeRequested`) and the handshake completed with `Request.respondWebSocket` (std does SHA1+base64+101); a plain `GET /api/stream` → 426. **(b) Per-connection threads (§9.1 lifetime rule):** the upgraded socket is handed to a dedicated stream thread that owns its own `Reader`/`Writer`/`WebSocket`/buffers in ITS frame (the 101 is written on the server's shared writer, then the thread builds a fresh Reader/Writer over the same socket — the post-handshake protocol is raw WS frames) and `close()`s the socket on exit; the accept loop keeps taking serial control connections and does NOT close a claimed socket. Stream threads NEVER touch `arena`/`resp_buf`/`body_buf`/`read_scratch`. **(c) Connection cap N=4** (a fixed-array registry guarded by a clockless `Io.Mutex`) — the 5th upgrade → 503 (no `respondWebSocket`). **(d) Shared latest-frame buffer** `src/api/shared_frame.zig` (`SharedFrame`: `seqno: atomic(u64)` + `Io.Mutex` + body): the producer copies index+palette+scalars in UNDER the mutex, bumps `palette_seq` iff the palette changed, computes `Wyhash(index++palette)`, then `seqno.fetchAdd(.release)` + `broadcast`; consumers `currentSeqno().load(.acquire)` as the "new data?" gate but read the BODY ONLY under the mutex into a per-thread buffer (no broken lockless seqlock). A clockless `Io.Condition` parks consumers (no busy-spin, no clock) and `wakeAll` unblocks them at shutdown. **(e) Frame producer** `StreamHub.produceFrame` (driven by the pacer each fps tick — 30 fps, capture every Nth ~10 ms slice): `submit(framebuffer_get)` (the existing cycle-neutral peek into the server-owned `RenderBuffers`) → publish into `SharedFrame`; no-op when no client is connected; an unsupported video mode publishes an "unsupported" marker (a `{"event":"unsupported"}` text control frame), never fabricated pixels. **(f) Raw-indexed wire** (§6.3): a 22-byte little-endian header (magic `ZD`/version/flags{has_palette,unsupported}/seqno(u32)/width/height/kind/pel_mask/index_len/palette_len) + index bytes + (when changed) 768 palette bytes, sent via `WebSocket.writeMessage(.binary)` (std picks the 64-bit length form for the >64 KiB frames). **(g) Dedup (Wyhash):** per-connection `last_hash` over index+palette together — an unchanged frame is skipped, a PALETTE-ONLY change IS sent (the key correctness case); a full frame is always sent on connect; the palette is included whenever `palette_seq` changed since that connection last sent it. **(h) Auto-start/run-ownership:** first stream connect auto-arms the pacer ONLY when idle (never hijacks a paused debugger session); last disconnect auto-stops it (only when paced owns the run). **(i) Shutdown ordering (§9.1):** `joinWorker` runs pacer-stop/join (pre-shutdown hook) → `StreamHub.shutdown` (stop-flag + socket shutdown + `wakeAll` + join all stream threads) → THEN the worker `shutdown_worker` sentinel, so no producer/consumer can be mid-`submit` when the sentinel goes in. **Determinism (CLAUDE #4):** pure host-side observation — the only machine access is `framebuffer_get` through the gated queue (charges no cycle); `shared_frame.zig`+`stream.zig` are CLOCKLESS and added to the `src/api` determinism grep-gate (the fps clock stays in `src/host` — §5.1a). Tests: hermetic `stream_test.zig` (SharedFrame publish/copyOut/palette_seq, the palette-only-change hash, `waitNext`/`wakeAll`, the §6.3 header, producer cycle-neutrality) folded into `test-api`; real-socket WS tests in `server_integration_test.zig` (101+correct accept key, 426, a valid raw-indexed frame round-trip with header parse, the 503 cap, two concurrent clients, clean shutdown with live connections). `zig build test` green, 514 tests; blackbox 14/14; `--serve` boots with the stream hub + pacer wired. The WebGL2 player page + input round-trip are the next phases. → `plans/video-stream-api.md` (Phase 3 / §4/§6/§9.1).
